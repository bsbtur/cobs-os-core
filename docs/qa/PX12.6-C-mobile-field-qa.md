# PX12.6-C — Mobile / Field QA

Date: 2026-08-15
Branch: `preview/alpha-productization-px01`
Scope: Journey live runtime (`operations/$operationId/live`) and field interaction reliability.

## Gate

Status: **BLOCKED — P1 reliability fixes required before field smoke test.**

The live runtime is already responsive and uses generally appropriate mobile spacing, but the following reliability conditions must be fixed before PILOT-03.

## P1 — Silent partial-query failure can masquerade as valid operational state

The `live` query runs operation, steps, feed events, resolution events, boarding/arrival events, presence, checklist items, checklist executions, roster and `w04_operation_runtime_state` in parallel.

Today only these errors are explicitly thrown:

- operation
- steps
- resolution events
- boarding/arrival events

Errors from the following requests are currently not promoted to the page error state:

- visual journey events feed
- participant presence events
- playbook items
- playbook executions
- operation roster
- `w04_operation_runtime_state`

### Risk

A failed request may be rendered as an empty collection or null state and look like valid operational truth.

### Required fix

Fail closed. Validate every load-bearing request before returning the live projection. The field UI must show an explicit retryable error state instead of substituting empty operational truth.

## P1 — Missing readiness must never default to ready

Current action wiring uses a permissive fallback equivalent to:

`ready={readiness?.ready ?? true}`

If runtime-state resolution is unavailable, gated actions can therefore look enabled.

### Risk

The UI can visually authorize completion/departure while readiness is unknown. Backend invariants remain the final defense, but field UX must never represent unknown as ready.

### Required fix

Fail closed:

- unknown readiness => `ready = false`
- render a visible "readiness unavailable" state
- disable readiness-gated actions until runtime state is successfully resolved

## P1 — Runtime actions should be disabled outside an active operation

The page displays a warning when `operation.status !== 'active'`, but live controls may still be rendered, including step start and current-step actions.

### Required fix

Pass an explicit `operationActive`/`canMutateRuntime` contract into runtime action components and disable mutation controls when the operation is not active. Backend authorization/state checks remain mandatory.

## P2 — Disembarkation blocked-state copy is misleading

The primary presence action blocks `DISEMBARKED` until `ARRIVED` exists, but the visible blocked hint currently uses the boarding-not-open copy.

### Required fix

Use arrival-specific copy for disembarkation and boarding-specific copy for boarded presence.

## P2 — Mutation dialogs should not close while a write is pending

Absence/no-show and presence-correction dialogs can currently be dismissed while the mutation is in flight.

### Required fix

Prevent dismissal while pending, matching the Journey editor hardening already applied in PX12.6-B.

## P2 — No-show menu action should respect shared presence mutation pending state

`ABSENCE_NOTED` is disabled while `record.isPending`, but `NO_SHOW_CONFIRMED` is not consistently disabled in the same menu.

### Required fix

Disable all presence-write alternatives while the presence mutation is pending.

## P2 — Mobile touch targets

The most important presence and step-action buttons already use ~48px minimum height on mobile. Checklist action buttons and three-way roster filters are smaller.

### Required fix

For field mode, target >= 44px for actionable touch surfaces, preferably 48px for primary operational actions.

## UX direction

Preserve the COBS Cockpit principle:

> In operation, COBS shows less information and more direction.

Field hierarchy should remain:

1. current step
2. current timing / delay
3. blockers and readiness
4. next best action
5. required people/checklist execution
6. secondary domain cards and timeline

Do not add new product scope during PX12.6-C.

## Exit criteria

PX12.6-C can move to field smoke test only when:

- all load-bearing live queries fail closed;
- unknown readiness cannot enable gated actions;
- live mutations are disabled outside active operation;
- presence mutation races/dismissals are hardened;
- touch targets are acceptable on phone viewport;
- current-step and next-action hierarchy remains visually dominant;
- a current preview deployment is available for the branch.
