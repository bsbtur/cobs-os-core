# PX12.6-C — Field Runtime Server-Side Smoke Gate

Date: 2026-08-15
Branch: `preview/alpha-productization-px01`
Environment: Supabase `COBS OS CLEAN BUILD` (QA only)
Production: untouched

## Objective

Prove that the field runtime fails closed at the canonical backend after an operation is completed.

## Fixture used

Existing QA operation in `completed` state. No new permanent operational fixture was created for this gate.

## Checks

### Runtime projection

`w04_operation_runtime_state` returned `status = completed`.

Result: PASS.

### Checklist mutation after completion

Attempted `complete_playbook_item` on an existing active playbook item belonging to the completed operation.

Expected: reject.

Observed backend error:

`Checklist runtime can only be changed while the operation is ready or running`

Result: PASS — blocked as expected.

### Journey step completion after operation completion

Attempted `complete_journey_step` on an existing step belonging to the completed operation.

Expected: reject.

Observed backend error:

`A journey step can only be completed while the operation is running`

Result: PASS — blocked as expected.

### Presence mutation after completion

Attempted `record_presence_fact` on an existing participation and step belonging to the completed operation.

Expected: reject.

Observed backend error:

`Presence can only be recorded while the operation is ready or running`

Result: PASS — blocked as expected.

## Gate conclusion

Server-side field runtime state guards are healthy for the tested completed-operation boundary:

- runtime projection preserves completed status;
- checklist runtime is closed;
- step completion is closed;
- presence runtime is closed.

No production data was touched.

## Remaining blocker before field smoke test

Frontend `LiveRuntimePage` still requires the PX12.6-C fail-closed UX patch documented in `docs/qa/PX12.6-C-mobile-field-qa.md`:

- promote every load-bearing query error;
- unknown readiness must default to blocked, never ready;
- disable active-runtime mutations outside `active` (while preserving the canonical `ready -> start journey` entry flow);
- harden presence dialogs and mobile touch targets.

Do not advance the Mobile/Field gate to PASS until the frontend patch is implemented and a current preview build is available.
