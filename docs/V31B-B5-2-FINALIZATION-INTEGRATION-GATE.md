## Objective

Prove the lifecycle atomicity contract for operation completion:

`operation -> completed -> Score Engine finalizes -> frozen snapshot -> audit -> RPC read-only summary`

The same database transaction must own the whole sequence. No exception after the operation update may leave a half-completed operation.

The lifecycle adapter deliberately does not catch evaluator exceptions. `public.set_operation_status` first persists `status='completed'` and `completed_at`, then synchronously invokes `app_private.finalize_operational_excellence_for_lifecycle`. PostgreSQL statement/transaction rollback therefore remains the failure boundary.

## Gate invariant 3 — forced post-UPDATE failure rolls everything back

Precondition was reset and committed before the adversarial call:

- operation status: `active`
- `completed_at`: `NULL`
- snapshot count: `0`

Failure was then injected by making the active score model unavailable in the same SQL transaction immediately before invoking the lifecycle RPC. This causes the Score Engine to raise only after `set_operation_status` has executed its operation UPDATE.

Observed exception chain:

```text
score_model_not_found
  -> evaluate_operational_excellence(uuid,boolean)
  -> finalize_operational_excellence_for_lifecycle(uuid)
  -> set_operation_status(uuid,text,text)
```

State after the failed transaction:

- operation status: `active`
- `completed_at`: `NULL`
- total snapshot count: `0`
- final snapshot count: `0`
- active score model count: `1` (the failure-injection mutation was itself rolled back)

This proves that the lifecycle UPDATE, score persistence and failure injector all share the same transaction boundary. No operation remained half-completed and no score snapshot survived partially.

Result: **PASS**.

## Decision

**B5.2 — PASS.**

All three minimum invariants are proven in the sandbox:

1. valid close => `completed + completed_at + final frozen snapshot`;
2. same RPC => final snapshot id/read-only Operational Excellence summary;
3. unexpected Score Engine failure after lifecycle UPDATE => full rollback, leaving `active + completed_at NULL + zero partial/new snapshot`.
